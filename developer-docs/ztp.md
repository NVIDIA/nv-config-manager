# ZTP Service

The ZTP service provides device bootstrap scripts, startup configuration files, OS image metadata, file downloads, SFTP access, and provisioning completion callbacks.

## Flow

1. A device receives DHCP options generated by the DHCP service.
2. The device downloads a boot script from ZTP.
3. The boot script downloads rendered or intended configuration from Config Store.
4. The device applies configuration and calls the provisioned endpoint.
5. ZTP updates Nautobot status and workflow metadata.

## API

```bash
curl -k https://ztp.config-manager.local/health
curl -k https://ztp.config-manager.local/v1/boot/<serial>
curl -k https://ztp.config-manager.local/v1/config/<device>
curl -k -X POST https://ztp.config-manager.local/v1/provisioned/<device>
```

The OpenAPI spec is `docs/api-specs/ztp.openapi.json`.

## Runtime Configuration

```ini
[ztp]
api_service = http://nv-config-manager-ztp-api:8000
api_url = https://ztp.config-manager.local
user_domain = local.config-manager.local
use_internal = true

[nautobot]
url = https://nautobot.config-manager.local
```

## OS Image Storage

The installer supports two ZTP image storage modes:

| Mode | Description |
| ---- | ----------- |
| `file` | Installer creates or reuses a PVC, uploads image files, and writes `manifest.json` |
| `s3` | ZTP reads objects and metadata from an S3-compatible bucket |

File-backed images are configured in `infrastructure.ztp_storage` in `nv-config-manager-install.yaml`.

## Local Development

```bash
uv run uvicorn nv_config_manager.ztp.api.main:app --reload --port 8080
uv run pytest src/tests/ztp/
uv run pytest src/tests/integration/test_ztp.py -v
```

Deploy with ZTP enabled by setting `services.ztp: true` in the installer config.
